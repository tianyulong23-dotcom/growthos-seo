## 结论

D6 的后端领域流程已经达到本阶段验收门槛：用户可以把一个种子词作为手动请求提交，系统仍按 CP-03、CP-04、CP-06 的完整准备链处理，而不是直接把输入词当成主词；已有 30 个自动计划项时，手动项成为第 31 项，不替换、不移动原来的 30 项。计划项编辑支持乐观锁、同步字段修改、种子词或主词异步重准备、人工标题和方向保护、日期冲突回滚，以及旧准备晚返回保护。

四个 CP-10/CP-11 接口已经注册并写入平台 OpenAPI。接口认证、项目隔离、状态码和结构化冲突信息均有 API 测试。

但生产异步接线还没有完成。当前生产构造器没有准备任务 Dispatcher、内容计划 Temporal Workflow，也没有接入 D3 的真实 Related Keywords/AI 网关和 D4 的真实 SERP/预览 AI 网关。因此，线上 HTTP 手动请求目前能鉴权、校验幂等并可靠落库为 `queued`，但不会自动消费到计划项完成。专项测试证明的是完整领域流程和数据库行为，不能把它说成生产环境已经端到端可用。

## CP-10 手动添加计划

- `POST /api/v1/projects/{project_id}/content-plan/items` 接受非空种子词，并要求 `Idempotency-Key`。
- 请求先使用服务端认证上下文确认组织和项目，再检查幂等键和关键词冲突；未授权请求不能探测业务合同。
- 明确命中已有计划或文章时，在付费拓词之前返回稳定冲突，不调用 Related Keywords。
- 手动输入保持为种子词，准备过程继续执行：拓词、AI 分类、信息型主词选择、关键词包、SERP 和预览。
- 手动批次独立保存外部请求账本、准备状态和失败信息；重复同一请求只创建一个批次、一个准备和一个计划项，并发重复请求也相同。
- 次关键词按真实分类类型和原顺序保存，正式包不超过 8 个；没有相关词时不为了凑数量写入无关词。
- 真实 PostgreSQL 组合测试先创建并排期 30 个自动项，再执行完整手动准备链。结果总数为 31，原自动项的 ID、`plan_order`、日期、状态和版本全部不变；手动项跳到未占用日期。

## CP-11 计划项编辑

- `GET /api/v1/projects/{project_id}/content-plan/items/{item_id}` 返回完整关键词包、标题和方向来源、当前 SERP 快照引用、待准备版本及错误，以及关联文章的审核和交付状态。
- `PATCH /api/v1/projects/{project_id}/content-plan/items/{item_id}` 必须携带当前 `version`。旧版本返回 `409 stale_version` 和服务端当前版本。
- 标题、写作方向、次关键词和发布日期同步修改；标题和方向分别设置人工编辑锁。
- 次关键词修改会验证归属、类型、相关性、重复和数量，不重新查询 SERP。AI 校验期间若计划版本变化，整包修改返回旧版本冲突，不覆盖新内容。
- 修改种子词会创建新准备版本并完整重跑；修改主词会先检查信息型、覆盖和计划重复，再查询 SERP，但不重新拓词。
- 重准备期间保留当前关键词包、标题、方向和日期，并设置 `edit_state=repreparing`；调度器不会领取这个计划项。
- 连续修改会继续增加准备版本。旧准备即使晚返回，也只能保留自己的历史结果，不能覆盖当前版本。
- 新准备成功时原子切换关键词包和 SERP。系统标题和方向可以更新，人工锁定字段保持原值。
- 新准备失败时保留旧内容，并进入 `reprepare_failed`；计划项不会按旧内容被调度领取。
- 发布日期冲突返回 `conflict_id` 并回滚；修改到项目时区中的今天或明天时，事务提交后立即调用现有文章生成入口。
- 取消接口为 `POST /api/v1/projects/{project_id}/content-plan/items/{item_id}/cancel`，使用版本校验；取消后待准备的晚返回不能恢复计划项。

## API 和权限

已注册接口：

- `POST /api/v1/projects/{project_id}/content-plan/items`
- `GET /api/v1/projects/{project_id}/content-plan/items/{item_id}`
- `PATCH /api/v1/projects/{project_id}/content-plan/items/{item_id}`
- `POST /api/v1/projects/{project_id}/content-plan/items/{item_id}/cancel`

读取要求 `content:read`，创建、编辑和取消要求 `content:write`。组织 ID 和实际项目 ID 只取服务端解析结果。跨项目读取或修改统一返回 `404`，避免泄露另一个项目的计划项。

手动创建和异步重准备返回 `202`；同步编辑返回 `200`；缺少幂等键返回 `422`；版本、日期和关键词冲突返回带稳定错误码的 `409`。

## 开源参考边界

- CP-10 严格按调研文档复用 CP-03、CP-04、CP-06 的内部准备链，只把入口缩小为一个种子词。没有把输入词直接写成主词或日历项。
- CP-11 的日历交互只参考 FullCalendar `packages/preact/src/api/EventImpl.ts` 的 `EventImpl.mutate()` 和 `revert()`，以及 `packages/preact/src/event-crud.ts` 的 `EventDropInfo` 合同：后端成功后保留新日期，失败时前端调用 `revert()`。D6 只完成后端日期合同，实际拖动交互属于 D7。
- FullCalendar 不负责排期算法、时区、一天一篇、版本校验或数据库保存。
- 乐观锁、准备版本、`pending_preparation_id`、人工字段锁、失败保留旧内容和旧工作流晚返回保护，都是建立在本项目 SQLAlchemy、PostgreSQL 和恢复要求上的本项目实现。

## 生产接线差距

以下内容不是测试失败，而是当前生产构造器中确实尚未实现的接线：

- 没有 `PreparationDispatcher` 实例，创建或异步编辑后不会派发准备任务。
- 没有内容计划 Temporal Workflow 或对应 Worker 消费准备记录。
- D3 生产构造器的种子、Related Keywords 和分类网关仍是 `_UnconfiguredGateway`。
- D4 生产构造器的 SERP 和预览 AI 网关仍是 `_UnconfiguredGateway`。

因此，本阶段可以确认 CP-10、CP-11 的后端合同、状态机、数据库事务和 API 边界正确，但不能确认线上真实 DataForSEO 和 AI 会由 HTTP 请求自动跑完。后续应把这部分作为独立的生产编排接线任务完成，并用真实供应商沙盒或受控账号验证整条请求到计划项落地流程。
