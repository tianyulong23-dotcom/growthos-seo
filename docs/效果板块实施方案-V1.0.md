# 效果板块实施方案 V1.0

## 1. 第一版目标

效果板块第一版只解决一个问题：

> 平台发布或优化的文章，在 Google 搜索中表现如何，哪些文章需要继续优化。

数据以 Google Search Console（GSC）为准。文章通过真实发布 URL 与 GSC 页面数据关联。

第一版不做：

- 外链监控
- 全关键词库每日排名
- DataForSEO 全量排名采集
- Bing、AI 搜索引用
- GA4 转化、收入和预估价值
- 自动判断内容下降的具体原因

### 第一步：确定文章与 URL 的关系

- 只选择发布成功的文章
- 优先使用发布记录的 `remote_url`
- `wordpress_url` 只作为兼容回退
- 不使用标题或 slug 猜测 URL
- 保存文章 URL 的规范化结果和明确的 URL 别名
- `www`、重定向、canonical 不一致时不能自动认定为同一个页面

当前可复用数据：

- `backend/api/app/modules/content/schemas.py` 中的 `ArticlePublicationResponse`
- `frontend/src/api/articles.ts` 中的文章和发布记录接口

### 第二步：同步并保存 GSC 数据

新增效果模块的数据表：

- `performance_sync_runs`：记录同步时间、状态和错误
- `article_performance_targets`：记录文章与发布 URL 的绑定
- `gsc_site_daily`：保存全站每日指标
- `article_gsc_daily`：保存平台文章每日指标
- `performance_signals`：保存当前信号及处理状态

同步规则：

- 首次连接后回填最近 180 天，支持展示 90 天并与前 90 天比较
- 每天自动同步一次
- 每次重拉最近 7 天，覆盖 GSC 延迟修订
- GSC 页面数据完整翻页，不能在 25,000 行处静默截断
- 同一项目的同步由数据库唯一约束保证严格互斥
- 保存数据截止日期和最后同步时间
- 同步失败时保留旧数据，并明确显示失败状态

当前 GSC 授权和查询服务继续复用：

- `backend/api/app/modules/settings/gsc.py`
- `backend/api/app/api/routes/data_sources.py`

### 第三步：增加效果专用 API

建议接口：

```text
GET  /api/v1/projects/{project_id}/performance/overview
GET  /api/v1/projects/{project_id}/performance/articles
GET  /api/v1/projects/{project_id}/performance/articles/{article_id}
POST /api/v1/projects/{project_id}/performance/sync
POST /api/v1/projects/{project_id}/performance/signals/{signal_id}/resolve
```

职责：

- `overview` 返回全站趋势、平台文章统计和增长/下降文章
- `articles` 返回可分页、筛选和排序的文章效果列表
- `articles/{article_id}` 返回趋势、历史 URL 聚合后的实际查询、发布/更新事件和更新前后 14 天对比
- `sync` 手动触发一次同步，但不能重复启动同一个同步任务
- `resolve` 记录信号已查看或已处理

不要让前端分别请求全部文章和 GSC 表格后自行关联。

### 第四步：实现状态规则

状态和信号必须在后端统一计算，前端只负责展示。

默认比较最近 28 天和前 28 天。满足以下情况时不判断下降：

- GSC 数据窗口不完整
- 发布时间过短
- 当前或上一周期样本量不足
- 文章刚更新，仍处于观察期

所有阈值集中配置并写单元测试，不能散落在前端组件中。阈值上线后根据真实项目数据调整。

### 第五步：替换现有效果页

修改位置：

- `frontend/src/features/performance/performance-workspace.tsx`
- `frontend/src/pages/performance-page.tsx`
- 对应前端 API 和测试文件

删除现有效果页中没有真实数据源的静态数字、转化、预估价值、Bing、AI 引用和外链内容。

必须包含以下页面状态：

- 正在加载
- 未连接 GSC
- 尚无已发布文章
- 等待 GSC 数据
- 正常展示
- 同步失败但仍有历史数据
- 接口读取失败
- 实际查询读取失败（与“暂无查询数据”明确区分）

## 4. 实施顺序

1. 编写 URL 关联、周期比较和状态规则测试。
2. 新增效果数据表和迁移。
3. 实现 GSC 回填、每日同步和失败记录。
4. 实现效果总览、文章列表和文章详情 API。
5. 替换前端 Mock，完成总览和文章列表。
6. 完成文章右侧详情及实际查询展示。
7. 接入“打开文章优化”和优化后观察状态。
8. 使用真实 GSC 项目完成浏览器验收。

## 5. 验收标准

- 未连接 GSC 时不显示任何假数据
- 只统计平台真实发布或优化过的文章
- 文章通过真实发布 URL 与 GSC 页面匹配
- 任意有数据的文章可以看到对应的 GSC 实际查询
- 文章 URL 变更后，同日指标和实际查询按文章正确合并
- 文章列表可以分页、按状态筛选并按有限指标排序
- 可以切换 7 天、28 天和 90 天
- 可以查看当前周期与上一周期的变化
- 样本不足时不生成下降信号
- 发布和更新事件能出现在文章趋势中
- 更新后的文章进入观察期，并可查看更新前后效果
- 页面显示 GSC 数据截止日期和最后同步时间
- 已查看信号在条件持续期间不重复生成；条件消失后才允许以后重新触发
- 现有 Mock 数字、转化、价值、Bing、AI 引用和外链内容全部移除
- 外链和独立关键词排名不进入本次实施
