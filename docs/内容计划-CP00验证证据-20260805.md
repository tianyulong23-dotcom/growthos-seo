# 内容计划 CP-00 验证证据

> 验证日期：2026-08-05  
> 端点：`POST /v3/dataforseo_labs/google/related_keywords/live`  
> 结论：原“单次 HTTP 请求提交 30 个 task”合同未通过；用户已接受 ADR-CP-0001 方案 A，优化合同通过 MockTransport 合同测试，真实费用验证仍受有效凭据阻塞。

## 需求合同

主需求第 12 节要求：

- 只发出一个 HTTP 请求；
- 请求体包含 30 个带唯一 `tag` 或等价标识的种子请求项；
- 返回 30 个任务 ID、逐项状态和费用；
- 若端点不接受 30 项，提交 ADR 并停止，不得静默拆成 30 次调用或改变批量大小。

## 官方合同证据

DataForSEO 的 Related Keywords Live 官方文档：

- URL：<https://docs.dataforseo.com/v3/dataforseo_labs-google-related_keywords-live/>
- 文档原文：`each Live API call can contain only one task`。
- 同一段说明最多每分钟 2000 次 API 调用、最多 30 次并发；这里的 30 是并发调用数，不是单次 HTTP 请求可携带的 task 数。
- 请求字段为单数 `keyword`，即一个 task 对应一个种子词。
- `tag` 是单个 task 的用户自定义标识，响应会在该 task 的 `data` 对象中回显；它不能把一个 Live 调用扩展成 30 个 task。

因此，需求中的“一次 HTTP 请求包含 30 个种子请求项”与供应商当前 Live API 合同直接冲突。

## 实际请求补充证据

在核对官方限制前，曾使用当前唯一配置执行一次最小 30 项请求：

| 证据 | 实测值 |
|---|---:|
| HTTP 状态 | `401` |
| DataForSEO 状态码 | `40100` |
| 返回任务数 | `0` |
| 实际费用 | `$0` |
| 分类 | `blocked_by_credentials` |

这次 401 发生在供应商接受任务前，本身不能证明 30 项是否受支持，也不能验证计费。CP-00 的“不支持”结论来自供应商官方合同，不来自这次 401。

## 优化合同和门禁判断

用户已接受 ADR-CP-0001 方案 A。优化后的 CP-00 合同为：

1. 一个内容计划逻辑批次最多接收 30 个种子。
2. 每个 HTTP 请求体严格只包含一个 Related Keywords task 和一个 `keyword`。
3. 由服务端受控并发，不由前端逐词发起。
4. 每项使用唯一 `tag` 和 `request_index`，响应必须通过回显 `tag` 可靠归属。
5. 每项独立保留供应商请求 ID、状态、结果、费用和错误；部分失败不丢失其他组。
6. 批次费用按逐项实际 `cost` 汇总，不沿用原单次批量费用公式。

合同测试位于 `backend/workers/tests/test_content_plan_related_keywords_contract.py`，覆盖 30 项单 task 序列化、结果保序、tag 映射、空结果、部分网络错误、供应商请求 ID、费用和并发上限。该测试使用 MockTransport 验证公开合同，不代表真实付费调用。

因此 D1 的工程合同门禁已通过，可以进入 D2。当前凭据仍返回 401，真实费用基线和账户级限流表现必须在有效凭据可用后补测；在此之前不得展示未经验证的预计总价。
