## 2. 产品规则

### 单池、批次与分页

- 只有一个推荐池，不要求用户选择发现来源。
- 新批次最多100条，不改变历史批次内容。
- 每页35条，100条显示为35/35/30；翻页不生成批次、不调用采集。
- 先对完整筛选结果进行搜索、过滤和联系方式优先排序，再分页。
- 单次库匹配最多保留1000个合格去重候选，不全部展示或启动联系方式采集。

### 来源分配

保留用户确认的首两批均分特例：

| 首轮合格 DataForSEO 数量 | 第一批 | 第二批 |
|---|---|---|
| 200 | 100 DataForSEO | 100 DataForSEO |
| 120 | 60 DataForSEO + 最多40库资源 | 60 DataForSEO + 最多40库资源 |
| 50 | 25 DataForSEO + 最多75库资源 | 25 DataForSEO + 最多75库资源 |
| 0 | 最多100库资源 | 最多100库资源 |

取 N=min(合格余量,200)，两批分别分配 ceil(N/2)、floor(N/2)，资源库补缺。库不足允许部分批次，不凑数。

之后每批先消耗已有合格 DataForSEO 余量，不足100才补库资源，不在第三批强制换来源。
例如450条：前四批各100条 DataForSEO，第五批50条加最多50条库资源。
已有合格余量与资源库都不足时，才按原有预算和停止条件调用 DataForSEO 补充。

“合格”需经过现有 V2 匹配、项目全历史去重与巨型站点排除，不等于供应商原始返回量。
复用现有 generation、发布记录和候选状态记录分配及剩余供应；不把 provider discovery round 当作用户发布序号。
新规则从启用后的新供给批次开始，刷新、重试不能重置首两批分配。不重写历史记录。
仅在现有字段无法准确表达预留时增加最小持久化字段，不默认另建调度模型。
首两批均分是用户明确需求，不能为了简化改成50条全部发到第一批。首次分配基于现有发现任务结束时的合格结果，不为等凑200条额外增加搜索轮次。

### DR 与分类

- Ahrefs 只查询项目域名；资源网站使用库内 `ahrefs_dr`，不换算 DataForSEO Rank。
- 分类复用已确认业务资料。同语言、相关 niche 优先，邻近分类其次，不新增复杂审核。
- 优先使用已有分类/标签与少量静态类别别名映射，本次不新增AI分类调用。无可靠映射时降低分类排序优先度，不阻塞生成或假装已确认相关性。
- 缺 DR 不当成0，不声称此类库网站已经满足 DR 匹配。

初始参数建议如下，集中为少量常量，不建设配置平台：

| 项目 DR | 库网站优先范围 | 库选入部分中 DR>=60 的上限 |
|---|---|---|
| 0至不足20 | 0至不足30，不足放宽到60以下 | 10% |
| 20至不足40 | 10至不足50，不足放宽到60以下 | 20% |
| 40至不足60 | 25至不足60，搭配高 DR | 30% |
| 60至100 | 40以上搭配 | 默认40%，最高50% |

上述分桶是初始产品参数，不是 SEO 定律。比例以本批实际选入库资源数为分母，向下取整，不强行凑满。
DR 配比仅约束库资源；DataForSEO 网站继续原 V2 匹配，不因缺 Ahrefs DR 被丢弃。
Apple、Amazon、Android 等巨型站点独立排除，高 DR 客户也不豁免。
