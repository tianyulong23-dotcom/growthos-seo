## 说人话的结论

内容计划页面已经不再使用写死的演示数据，而是连接内容计划 API 和 PostgreSQL 数据库。用户现在可以在页面查看真实计划、打开详情、修改并保存计划、调整发布设置、取消计划、处理失败批次，以及立即创建文章任务。刷新页面后，已经保存的结果不会丢失。

本次验收确认了桌面端和手机端都能完成主要操作。日期冲突时，后端会拒绝重复日期，前端会恢复原日期并显示中文提示，不会把错误日期或错误版本写进数据库。失败批次重试后重新进入队列，已有外部请求次数和费用没有增加。

但这不等于验收环境已经在后台继续跑完所有任务。这个独立环境没有启动内容计划 Worker，因此失败批次只验收到“重新入队”，立即生成文章只验收到“唯一 Article 和 ArticleRun 已创建并进入等待执行”。不能写成批次已经恢复完成或文章已经生成完成。

## 前端接入范围

- 内容计划页面按当前项目读取真实计划列表、计划详情和发布设置。
- 月历和列表使用后端返回的日期、状态、标题、主关键词和关联文章，不再依赖 `initialPlans` 等本地假数据。
- 自动生成 30 个计划会创建真实批次，并轮询显示批次阶段、计划数量、外部请求次数和累计费用。
- 支持失败批次恢复与重试；后端不允许安全重试时，页面显示对应错误，不会绕过付费请求保护。
- 支持手动添加一个种子词，后端仍按异步准备合同处理。
- 计划详情读取完整关键词包、标题、写作方向、发布日期、准备状态和关联文章。
- 同步编辑支持标题、写作方向、次关键词和发布日期；修改种子词或主关键词使用“重新准备”入口。
- 支持取消计划和立即生成文章。
- 发布设置支持发布频率、暂停开关和项目时区，并携带当前版本保存。
- 页面使用项目路由中的 `projectId` 调用 API，没有把验收项目 ID 写死在产品代码中。
